# Methodology
1. **Load**: Pillow reads metadata; OpenCV decodes pixels. Originals in `data/raw/` are never modified or overwritten (uploads get a numeric suffix).
2. **Preprocess** (grayscale, CLAHE contrast, Gaussian denoise, min-max normalize, resize, or an optional pipeline) on copies only. Copies are saved under `data/processed/`. Gaussian kernel size must be odd; sigma `0` lets OpenCV derive sigma from that size.
3. **Detect**: `findChessboardCornersSB`, then the same call with `CALIB_CB_EXHAUSTIVE` if needed, then `findChessboardCorners`. Detected corners are refined with `cornerSubPix` when the window fits. The caller supplies the inner-corner pattern; OpenCV must see the **entire** pattern. Failure returns an explanation and no coordinates.
4. **Geometry** (`distortion_analyzer`): neighbour spacing and row straightness in pixels, plus the residual after a least-squares homography from a unit planar grid onto the detected corners. A homography can represent reflections and flips, so the corner labelling (which board corner OpenCV lists first) does not change the residual; this was checked on the SAFFIRE images (all four labellings equal to 6 decimals), and the grid is therefore labelled once. That residual is what perspective does not explain. It is not a lens coefficient (`k1`, `k2`, `p1`, `p2`, `k3`) and it is not a millimetre error. A deviation drawing is saved only when that residual was computed.
5. **Calibration**: `cv2.calibrateCamera`, only when at least `min_views` (default 10, configurable, a practical default rather than a NASA value) independent views detect. Rejected inputs: color/mono duplicates, combined composites, mixed resolutions. Reports RMS reprojection error and labels outputs as calculated. Square size is optional; without it, units are "square units".
6. **Undistort**: `camera_calibration.undistort` works only with a valid model.

## Panels (combined images)
`services/panels.py` finds a full-height bright vertical divider (every pixel below a label band >= 200) and splits there. A panel is called a duplicate of an individual file when the mean absolute grey difference (label band excluded) is <= 3.0; that threshold is a heuristic, chosen because JPEG re-compression of the same scene measured about 1. Camera identity is not determined by software.

## Observed on the supplied data
All numbers were computed from the supplied files (OpenCV 4.10.0 and 5.0.0 gave the same detections for the patterns below).

- **F1C1 (individual, color and mono):** the largest pattern that detected is 21×11 (231 corners), the central region only. Measured geometry (color): mean neighbour spacing 58.67 px (std 6.07, min 40.38, max 66.38), row-straightness RMS 8.05 px, homography residual RMS 15.86 px (median 13.57, p95 26.95, max 45.14). The mono file gives the same values to within about 0.01 px.
- **Combined images:** two panels. Panel 1 is the F1C1 image. Panel 0 is a different picture whose burned-in label reads F1C2 (read by eye). Panel 0 detects 20×10 (200 corners): spacing mean 59.18 px, row-straightness RMS 6.83 px, homography residual RMS 13.89 px.
- **What the residuals mean:** the large residuals agree with the strong barrel-type curvature visible in the images. They are pixel measurements on a partial region and are **not** distortion coefficients.
- **Calibration:** not possible with this data. After removing color/mono copies and the duplicate panel there are two distinct pictures, from two different cameras, one view each. A single planar view cannot constrain a camera model, and views from different cameras must not be pooled. The API returns `insufficient` and no camera matrix. Calibrating would need at least ~10 (configurable practical minimum, not a NASA figure) independent views of the same camera.
- **Why 6×4 is not recommended:** earlier notes cited a 6×4 detection. It does detect on these images, but it is a small sub-region and smaller sizes are inconsistent across OpenCV versions.
